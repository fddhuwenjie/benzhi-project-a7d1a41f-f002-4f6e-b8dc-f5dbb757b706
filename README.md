# 植物引种隔离放行工作台

这是面向植物园引种、生物安全审核和隔离圃观察团队的单流程 Web 应用。系统将外来植物材料从隔离建档、风险基线审查、连续观察、偏差限制与验证推进到放行或终止归档，并以 SQLite 事务保存修订号、幂等请求结果和只追加审计时间线。

浏览器工作台与同源 JSON 接口由同一个 Go 服务提供，不需要 Node.js 或其他前端构建链。工作台支持三类角色：引种管理员负责草稿资料修订、风险试算与提交；审核员负责限时清单、补录和偏差复核、资格确认与最终决定；观察人员负责窗口签到和偏差处置。详情同时展示资料缺口、观察趋势预警、逐项证据绑定、归档完整性及摘要指纹，工作台提供关闭结果汇总查询。

## 构建

项目要求 Go 1.23 或更高版本。在项目根目录执行：

```text
go build ./cmd/server
```

## 运行

默认监听高位回环地址 `127.0.0.1:19081`，数据库文件默认为当前目录下的 `quarantine.db`：

```text
go run ./cmd/server
```

也可以显式指定地址和数据库路径：

```text
go run ./cmd/server -addr=127.0.0.1:19091 -db=./data/quarantine.db
```

未提供 `-addr` 时，服务会读取 `PORT`，并绑定到 `127.0.0.1:<PORT>`；显式 `-addr` 的优先级更高。启动后在浏览器访问对应地址即可完成全部主流程。

## 测试与自检

运行全部单元测试和事务回归测试：

```text
go test ./...
```

运行有界 HTTP 全流程自检：

```text
go run ./cmd/server -self-check -addr=127.0.0.1:19081
```

自检使用临时 SQLite 数据库，启动真实 HTTP 服务，依次完成建档、风险试算、风险基线提交、批准、观察、资格核验和放行归档，校验修订号及审计事件后主动退出，不会留下业务数据库。

## 业务一致性

所有写接口都要求 `request_id`、`expected_revision`、`actor` 和 `role`，创建接口除外，不需要 `expected_revision`。仓储会在同一 SQLite 事务内校验 revision、保存业务聚合、记录幂等响应并追加审计事件。重复的 `request_id` 返回首次操作结果，不会再次推进状态；过期 revision 返回明确冲突。已放行或终止的个案只读。
